## 手机通道 World

这是给 Coo / Cortico 使用的手机通道。World 中的两个安卓通用模板不含个人连接信息；启用 World 后，可从「World 总览」卡片或手机安装指南生成与该 Coo 连接的专属安卓安装包。App 和原有 Tina App 使用不同包名，可以并存。苹果客户端提供源码及未签名 IPA；IPA 需要自行签名，尚未经真机验证。

安卓侧栏「公网 World」提供星邮官方网页入口，也能打开其他 World 提供的 HTTPS 网页。星邮域名首页连接失败时会尝试官方客户端公布的 HTTPS 备用地址；两个地址的网页登录状态分别保存。网站的账号与会话由对应网站处理；此功能不会代装 World 或将奶coo 的局域网连接变成公网连接。电脑上的 Coo 是否接入了星邮，仍取决于其实际安装和配置。

安卓右上角奶coo 图标可直达星邮「我的 bot」私聊，再点一次返回之前的页面；首次使用提供星邮流程引导。侧栏的原有对话与公网 World 入口继续保留。未登录时按星邮网页提示登录。

右上角图标可以跟随手机端的小人外观；在「随身小人」可添加随之更新的桌面快捷入口。系统原有应用图标保持独立，头像渲染失败时使用缓存或默认图标。

同一个入口也提供苹果配对、苹果客户端 0.2.2 源码、未签名 IPA、AltStore Windows 测试安装说明和两端的离线图文指南。未签名 IPA 可尝试通过 AltStore Classic 由使用者自行签名安装；本项目尚未完成该流程与苹果真机验证。World 不会自动构建或签名苹果安装包。安卓端可在“诊断日志”中预览并自行分享明文日志，侧边栏“图文使用指南”和各页面问号提供帮助。

手机左侧菜单「World 扩展」可查看当前部署返回的 World 并进入手机提示设置；此列表不保证包含所有已安装但未加载的扩展。手机市场目录暂不可用；市场、安装、卸载和运行控制请在电脑 Coo 中操作。旧版手机通道未提供这个目录时，手机会提示更新并仅显示已经观察到的事件来源，来源不等同于已安装 World。

苹果设备连接入口：World 0.3.23 候选新增电脑本地「苹果设备扫码连接」页面，二维码含单次、五分钟有效的配对码，不含长期密钥；成功兑换后凭据由苹果客户端保存。苹果客户端已收到模拟器编译记录，但真机测试和联调尚未完成，不能把该入口当成已有可安装 iOS 版本。当前兑换仍使用 World 共用令牌，暂不支持逐设备撤销。

0.3.24 候选扩展了附件类型并新增可选文件名；图片、语音、短视频和普通文件均保留原始字节，单个附件仍限 8 MiB。旧版 Android 对它不认识的文件类型可能无法直接预览；模型只有在确实支持该媒体或有相应工具时才能理解内容。安装前先取得 `mobile.sqlite` 的一致备份，新列不会删除旧数据。

0.3.25 增加向手机返回附件时的可选 `file_name`；如果调用工具时没有提供文件名且附件句柄无法解析出名称，接收端仍可根据 MIME 类型提供合理的打开方式。

## 第一次使用

1. 在 Coo 的「扩展 → World」中安装「移动前端coodock」，按 Coo 提示重启。首次安装后在「World 总览」启用它。启用后左侧会出现同名入口，旁边显示本机通道和公网中转状态。本版使用 World API 6 和 Node.js 24。
2. World 启用时自动生成并保留接入密钥、打开手机通道，默认选择可用的局域网地址。它不会安装模型或其他 World。选择其他网卡或 VPN 地址时，在 World 设置中填写「手机访问的地址」，重启该 World 并重新下载手机包。
3. 在运行 Coo 的电脑打开「World 总览」，找到已启用的「移动前端coodock」卡片。安卓主机直连使用「下载安卓 APK（本机专属）」。使用公网中转时，从[公网主页](https://htina.top/)（[备用入口](https://8.137.59.209/welcome)）领取密钥，再在本机打开「填写公网密钥并生成专属 APK」。苹果测试包和配对入口在「手机安装与连接指南（安卓 / iOS）」。安卓首次打开通常会读取连接；已有连接的旧安装不会被自动覆盖，要切换时在 App 的「连接」页点「使用此安装包的 Coo 连接」。
4. 专属包带有配对信息，请只传给自己的手机。专属包只允许从运行 Coo 的机器生成，通用 World 包不含密钥。APK 签名保护程序本体；专属连接元数据可从 APK 读出。已被其他电脑连接器使用过的密钥不能再绑定此 World。公网中转只覆盖对话、消息同步和档位允许的媒体，Coo 控制台等主机直连功能仍需局域网或 VPN。

从 0.5.0-beta.4 升级时，Coo 中的 World ID 从 `milkcoo_app` 迁移为 `milkcoo-app`，以便 Coopanion 0.2.13 在侧栏显示详情。升级时沿用旧设置和可见性，以及原数据库和连接密钥。原有 Android 连接可继续使用。「本机通道」反映电脑监听状态，「公网中转」在电脑与中转服务连通后显示绿灯。

Coopanion 0.2.13 的「从本机目录安装」可能拒绝包含中文的路径，提示“路径含有不接受的字符”。遇到此提示时，可先把候选包解压到全英文目录，再选择其中包含 `package.json` 的文件夹。此限制属于本机目录安装路径检查，不代表 npm 市场安装也有同样的限制。

手机安装指南及苹果配对页面只允许主机本机访问。远程 Linux 主机可通过可信的远程桌面或 SSH 端口转发打开，不要为了取安装包而公开本机管理入口。
5. 回到「对话」。打字发送；「听写」调用手机已安装的听写服务；「图片」选择 JPEG/PNG/WebP；「拍照」调用系统相机并发送照片；「录音」开始录制，再点「停录」发送，最长 60 秒。输入框里已有文字会和图片/录音一起发送。每个媒体最大 8 MiB，断线时留在手机待发送。
6. 图片在对话中直接显示，点击可放大；语音点播放即可。也可对文字回复点「朗读」，使用手机系统 TTS。左上角菜单可打开事件、看屏幕、麦克风和连接设置；首次使用有简短引导，之后也能从菜单重新打开。

「桌宠」页可以开启系统悬浮小人：首次连接时从对应 Coo 的桌宠服务取得当前角色包和运行资源，在手机本地绘制、动画和触摸，离开 App 后继续显示。需要在手机系统授予「显示在其他应用上」；点按或拖动小人互动，在 App 或通知栏关闭。资源缓存按连接隔离，曾经下载完整的资源可供断线时继续显示；换角色所需的新资源仍需连接 Coo。多开 Coo 时可在 World 设置中指定对应桌宠资源端口。小人可以在整屏活动，只有小人附近的有限区域接收触摸，其余区域交给下方应用。

手机按全局游标增量同步当前 Coo 的事件库，而非仅接收手机自身的事件。事件页把此 Coo、已接入 World、手机离线待发送记录与回执按来源时间合成时间线，点击可查看原始记录；按设备和消息 ID 去除同一条手机输入的重复显示，原始记录本身不会被删除。不同设备的时钟可能不一致，同步不会把事件再次投入模型；没有投递证据时显示为未知，不把已记录冒充已进入对话。其他独立 Coo、DSH 或 Codex 只有在实际接入后才会出现在此时间线。

桌宠已记录的 `say` 会显示对应文字和表情，手机通道的新回复也能显示为气泡。World 提示保留事件来源，展示本身不会变成对模型的新输入。本版本不再镜像电脑桌宠的动作、工作或聆听状态；手机与电脑的位置互不覆盖。手机小人的外观资源可能通过宿主网页获取，是否可用取决于宿主版本。实时动作并不保证离线后逐个重演，桌面提问及回答仍留在电脑。手机触碰会先落本机待发送，再进入 Coo 的 `coo_mobile.pet_touch` 事件；默认随下一次对话投递（piggyback），不会每碰一次强制请求模型。

手机左侧菜单的「通知与提示」列出电脑已安装的 World 以及事件中见过的来源，可按来源控制允许打扰、小人气泡、通知栏、重要横幅、锁屏正文；也可先添加来源标识。默认允许提示进入气泡和通知栏，横幅和锁屏正文默认关闭。首次打开新版并允许通知后，会在手机本地显示一条带设置说明的示范；「试一条提示」可再次展示，不会发给模型。Android 的通知权限、通知类别、免打扰与锁屏设置决定最终是否显示，横幅也是通知栏中的一条通知。关闭提醒不删除事件时间线。

默认识别桌宠自己记录的发言及提问、事件类型或 `meta.kind` 明确标为 `notification` / `notify` / `notice` / `alert` / `alarm` / `reminder` / `prompt` / `tip` / `warning` 的消息，以及 `meta.notification` 提示。其他 World 若用普通文字事件表达提醒，可在该来源打开「也提醒普通文字事件」。若桌宠发言中没有上游 World 标识，只能归入 `desktop-pet`，不能猜测或保证追溯到发起 World。桌面提问只展示说明，回答仍需回原窗口完成。新服务器首次补历史时只存档不补发旧通知。

「随身小人」中可分别调整角色、气泡、悬浮按钮和菜单在这台手机上的透明度；不修改桌面外观，最小 20% 以保留可见的操作入口。Android 为允许触摸穿过透明悬浮层，可能对整体显示再施加上限。小人附近的快捷按钮停留时间比桌面默认延长 0.75 秒。

手机显示停靠式软键盘时，桌宠会尝试把键盘上沿作为临时地面，并在键盘升起时跳一下；键盘收起时从当时的高度下落，在屏幕底部回弹。正在拖动或已经腾空时由原来的触摸、身体动作优先。浮动键盘可能不向系统提供可用的键盘边界，悬浮窗也受不同手机系统限制，须以实际设备表现为准。

这里使用运行中 Coo 自身提供的桌宠网页与角色资源；它们各自的版权和许可证仍然有效。此 World 与通用 Android 包没有打包这些资源。与哪些第三方角色包兼容取决于该包所需的桌面能力和手机 WebView，须实机逐个验证；桌面窗口感知、Coo 本机语音、摄像头等不自动移植。

手机与 Coo 须实际可相互访问。电脑休眠、IP 改变、不同网段、防火墙阻断都会造成断线；断线的手机原文保留在本机，恢复后重试。后台运行与提醒仍受手机系统省电、通知权限和网络状态影响。

## Coo 里的行为

### 世界聊天

在电脑的「扩展」页更新到 `0.5.0-beta.6`，重启 Coo，再从「移动前端coodock」下载新版 Android APK 覆盖安装。手机上从「快捷抽屉 → 世界聊天 → 公共大厅」进入。已有公网中转绑定会自动沿用。只用过局域网或 USB 直连的用户，可以在「世界聊天」里点「绑定已有密钥」，也可以从 World 生成已配置公网连接的专属 APK。

绑定公网密钥后，在 World 控制台打开「世界聊天 · Bot 收听」选择是否收听。这个开关与同一中转账号绑定的手机同步，默认关闭。运行中开启时，从中转记录的开启位置开始，开启前的消息不会重播；若程序启动时已经开启，则从当时最新位置开始。每批至多八条，自己发的消息跳过，只有含人类新发言的批次会唤醒 Bot，其他 Bot 发言随下一次对话带入。关闭后 Bot 无法主动读取群聊内容，手机仍可正常查看和发言。

开启收听后，Coo 可用 `milkcoo_app_world_chat_read` 查看群聊和置顶公告；获用户授权后，可用 `milkcoo_app_world_chat_post` 发送文字或贴纸。`@` 后跟完整公开 ID，回复填写群聊消息 ID；贴纸使用群聊里的 `sticker_id` 或库里的精确文件名 `sticker_file`。普通手机消息继续走原来的私聊工具。

群贴纸可用 `milkcoo_app_world_chat_sticker_read` 查看；在当前模型接受 MIME 时交付实际图片，自动群聊事件一批最多附上一张人类发送的贴纸。Bot 想收藏时需另用 `milkcoo_app_world_chat_sticker_save` 显式写入自己的共用贴纸库。收听、查看都不会收藏。

首次读取可省略 `after` 查看最近消息，后续传回 `next_cursor` 读取增量。服务器执行禁言，若返回 `state: unknown`，可先读取群聊查看是否送达，或用相同 `client_id` 和原消息重试。该功能需要中转服务开放 `/relay/world-chat/*`。

`coo_mobile.message` 携带原文、设备 ID、消息 ID、时间，以及可选的原始媒体附件。它进入当前 Cortico 的事件流；仅当模型或已接入工具支持相应 MIME 时，才能直接理解媒体。否则事件保留附件并明确提示不可猜测，用户可使用手机听写或接入 ASR/视觉工具。

普通文字通过 `milkcoo_app_reply(device_id,in_reply_to,text)` 返回。其他 World/工具若已提供图片、音频或其他附件 `log:`/`mem:` 句柄，可用 `milkcoo_app_send_media(device_id,in_reply_to,handle,text?)` 返回该媒体；不存在的句柄会失败。这个包不自动提供语音识别、语音生成、图像生成，也不把文字朗读假装成服务端原声。安卓现有客户端支持 MP4/AAC、MP3、WAV 和 JPEG、PNG、WebP；其他格式的实际打开能力取决于接收客户端。

手机输入和服务端回复各有稳定 ID，重试相同内容不会重复产生事件；同一 ID 改变内容会报冲突。媒体与文本分别保存，传输通过 SHA-256 校验。手机 `/v1/feed` 只返回索引；屏幕附近的图片自动加载并缓存，语音在点击播放时加载。服务端已保存、进入会话、手机收到和人已读是不同状态。

World 数据库位于此部署的 `dataDir/mobile.sqlite`（含 WAL），保存媒体 BLOB 和消息；备份应取得 SQLite 一致快照。App 文字 JSON 导出目前不含媒体文件，媒体保存在 App 私有目录和 World 数据库。小 App 没有本机模型和共同记忆库，使用连接到的 Coo 部署已有的人格、记忆和工具。

## 本次验收范围

手机桌宠可在整屏范围内活动；小人、菜单和气泡的区域接收触摸，其他区域交给下方应用。系统安全页面可能隐藏悬浮窗。App 左上角菜单里的“看屏幕”进入设置，开启和停止按钮位于设置页顶部。小人菜单的“看一眼”或双击小人可主动请求一张当前屏幕，双击可在桌宠或屏幕设置页关闭。没有持续读屏时需接受 Android 的单次屏幕共享授权，捕获一张后停止；持续读屏已经开启时沿用当前授权取新一帧，不改变持续设置。看一眼通过手机消息与附件进入队列，使 Coo 可按原设备和消息 ID 回答，已投递的截图遵循 Coo 的事件留存规则。

持续屏幕感知须由用户开启，手机与电脑各有间隔和自适应设置。默认只供模型按需取最新一帧，不自动调用模型；主动查看会把画面送入对话并产生 API 费用。停止后清除暂存在 World 内存中的最新画面；已主动送入对话的事件遵循 Coo 原有留存规则。本版本不提供电脑屏幕感知；手机屏幕分享仍需用户明确开启。手机可选的无障碍服务只记录交互时间，不读取页面文字；部分游戏与系统不提供触摸事件。能否读懂图片取决于当前模型的媒体能力。

左侧「摄像头观察」由用户授权并开启前摄或后摄，在通知栏保持可见，可随时停止。手机本地显示预览，发送到 World 的最新帧在停止后从内存移除；用户主动观察时交给 Coo 的事件遵循 Coo 的留存规则。默认按需查看，不会为每帧请求模型。用户可选择省流、均衡、清晰，调整 2 至 120 秒的基础间隔，以及根据画面变化自动调节；Coo 可在已开启时通过工具调整画质、间隔与自适应，无法自行启动镜头或开启主动观察。打开主动观察最快约 15 秒唤醒一次模型；自适应时稳定画面只更新缓存，不重复唤醒，变化是和上一次主动送出的画面比较。图像 token 和处理速度由模型及 API 决定，降低 JPEG 文件大小不保证同比节省 token。这是图片抽帧与现有语音消息的组合，不是连续双向视频或语音通话。

“模型”页通过已连接的 Coo 控制台选择模型与思考强度，手机不接收模型 API Key；Coo 的 World 页面同时提供电脑端快捷面板和原生“模型连接”入口。两端修改的是同一套 Coo 设置，电脑读屏也可从快捷面板或手机开启。该设置可能影响使用同一模型连接的其他窗口，已发出的请求不改变。多开 Coo 时应先检查此 World 的控制台端口；控制台本身需要身份验证时，手机入口会提示不可用，不会绕过原有登录。

# 可选跨网组件 EasyTier（试验入口）

手机连接页中“跨网连接与组件”提供可选的 EasyTier 2.6.4 官方 Windows x64 安装程序和 Android arm64 APK 下载。点击明确下载按钮后，文件先进入 World 数据目录的 `easytier-downloads`，以固定的 GitHub 官方发布资产 SHA-256 和字节长度校验，校验成功才成为正式文件；已存在且校验不一致的同名文件不会被覆盖。下载不会安装、运行、创建虚拟网络或配置密钥。原局域网通道独立运行。

要组网仍需用户自行安装、配置，Android 可能需要 VPN 系统授权并与现有 VPN 冲突；直连或中继可用性须实测。EasyTier 的源码和发布包遵循 [LGPL-3.0](https://github.com/EasyTier/EasyTier/blob/v2.6.4/LICENSE)，本 World 不捆绑其二进制。校验值来自 [官方 2.6.4 发布资产元数据](https://api.github.com/repos/EasyTier/EasyTier/releases/tags/v2.6.4)。

安卓已有 VPN 时可尝试 EasyTier 的“高级设置 → 无 TUN 模式”。配置两端相同的网络名称、密钥和发现节点、不同虚拟地址，然后在手机端“端口转发”添加 TCP：绑定地址 **127.0.0.1**、绑定端口选择未占用端口，目标填写电脑的虚拟地址和 Coo 手机通道端口。奶coo 服务地址填写 `http://127.0.0.1:所选端口`，沿用原有连接密钥。请使用可信组网和服务器；不要将转发监听到所有网络接口。无 TUN 与现有 VPN 的共存、打洞和中继仍需在你的设备及网络上验证。
